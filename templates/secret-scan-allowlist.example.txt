# Secret-scan allowlist — values that are NOT secrets in this brain.
#
# Copy to  ~/.agent/.secret-scan-allowlist.txt  and edit.
#
# This is the inverse of redact-private.txt:
#   redact-private.txt          ADDS patterns    → more things flagged
#   .secret-scan-allowlist.txt  REMOVES findings → fewer things flagged
#
# One regex per line, matched (re.search) against the DETECTED VALUE,
# not the whole line. Blank lines and #-comments are ignored. A bad
# regex warns on stderr and is skipped — it never breaks the scan.
#
# Both gates honour this file: sync.sh's per-file quarantine
# (scan_gate.py) and the redact.py pre-commit hook. They have to agree,
# or an allowlisted file would be staged by one and rejected by the
# other.
#
# Only add a pattern once you have looked at the value and confirmed it
# is an identifier, a filename, or a placeholder — never because a scan
# is being noisy. Verified credentials are never allowlisted; they are
# quarantined no matter what this file says.

# ---- Examples (uncomment / adapt) ------------------------------------

# Google Drive / Docs / Sheets file ids. These are opaque identifiers,
# not credentials — access is governed by Drive ACLs, not by knowing the
# id. Drive folder ids are 33 chars, Docs ids 44, both starting with "1".
# ^1[A-Za-z0-9_-]{32}$
# ^1[A-Za-z0-9_-]{43}$

# Internal ticket / incident slugs, e.g. NOC-2026-08-0001234567890
# ^NOC-\d{4}-\d{2}-\d{10,}$

# A specific known-safe constant you got tired of seeing:
# ^my-well-known-non-secret-fixture-value$
